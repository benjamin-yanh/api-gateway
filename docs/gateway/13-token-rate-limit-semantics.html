Token limit semantics

Token 限流：请求、响应与 max_tokens

代码结论：当前限流器限制请求次数；响应结束后只记录成功请求；max_tokens 影响计费预扣，不参与实时响应限速。

代码时序

TokenAuth → ModelRequestRateLimit → check 总请求数/成功请求数 → c.Next() → Relay/Provider/SSE 或 WebSocket → status<400 时记录成功请求

计费：valid_request 校验 max_tokens → EstimateRequestToken → ModelPriceHelper → PreConsumeBilling → Provider Usage → SettleBilling

max_tokens 的实际作用

  • 请求校验：relay/helper/valid_request.go:124 及各协议校验器拒绝超上限值，返回 400。
  • 预扣估算：relay/helper/price.go:94-98 将显式 max_tokens 加入预计 completion tokens。
  • 阶梯计费：未传时使用 defaultTieredPreConsumeMaxTokens=8192 作为预扣估算回退。
  • 请求限流：middleware/model-rate-limit.go 不读取 max_tokens，100 和 100000 都只计为一次请求。

当前没有按 Token TPM 或输出速度实时限流。若要实现，需要新增按用户/Token/模型维度的 Token bucket，并在 Usage 或流式事件中扣减。
