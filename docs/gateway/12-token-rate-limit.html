Token 限流代码解析

本章区分访问 Token 的请求次数限流、Token 额度扣减和模型 Token 估算，避免把三个概念混为一谈。

总览 · 鉴权上下文 · Token 限流 · 计费 · 配置参考
适合：普通 Go 开发者、维护者阅读时长：8 分钟前置：Gin middleware、Redis 基础

先记住三个“Token”

概念代码是否限流
访问 Tokenmiddleware/auth.go:TokenAuth识别调用者，写入 user/token/group 上下文。
请求次数限制middleware/model-rate-limit.go:ModelRequestRateLimit按用户 ID、Token 分组在时间窗口内限制请求次数，超限 429。
模型 Token/额度service/billing.go:PreConsumeBilling、SettleBilling按估算和真实 Usage 扣减余额，不是 TPM 限流器。

请求执行顺序

Router /v1 或 /v1beta
  → TokenAuth
      → 解析 Authorization / x-api-key / Gemini key / WebSocket 子协议
      → ValidateUserToken
      → SetupContextForToken
          token id、user id、group、model limits、quota
  → ModelRequestRateLimit
      → enabled?
      → Token group，否则 user group
      → Redis 或内存限流
  → Distribute → Relay → 计费预扣/结算

路由挂载见 router/relay-router.go:69-73 和 router/relay-router.go:189-194。

ModelRequestRateLimit 的实现

  1. setting.ModelRequestRateLimitEnabled 为 false 时直接 c.Next()。
  2. 读取窗口、总请求数、成功请求数三个参数。
  3. 优先读取 ContextKeyTokenGroup，为空时回退到 ContextKeyUserGroup。
  4. 通过 setting.GetGroupRateLimit 覆盖全局限制。
  5. Redis 模式使用成功请求 List + 总请求令牌桶；无 Redis 时使用 common.InMemoryRateLimiter。
  6. 被拒绝时返回 HTTP 429；请求完成且状态码小于 400 时才记录成功请求。

当前限制单位是“请求次数/时间窗口”，不是输入或输出 Token 数。totalMaxCount=0 表示不限制总请求数；成功数默认仍由配置决定。

Token 额度路径

relay/helper/price.go
  → 估算 prompt/max_tokens/媒体和倍率
  → PriceData.QuotaToPreConsume
  → service.PreConsumeBilling
  → service.NewBillingSession
  → Provider
  → Usage 或本地回退
  → service.SettleBilling
  → 补扣 / 退款 / 记录 quota saturation

SetupContextForToken 将非无限 Token 的 RemainQuota 写入 token_quota；真正的余额校验和扣减由 BillingSession 及其模型层调用完成。
