标准排查顺序

  1. 用 Request ID 对齐 access/error/consume 日志，确认是否进入目标 Router。
  2. 检查 TokenAuth 写入的 user、token、using group；确认没有把访问 Token 与模型 Token 混淆。
  3. 检查 Distribute 的 specific channel、affinity hit、selected channel、priority/weight。
  4. 检查 RelayInfo 的估算 Token、PriceData、预扣结果；失败时确认 Refund 是否执行。
  5. 检查 Adaptor 的最终 URL、脱敏后的 Header、模型映射和上游状态码。
  6. 若发生重试，记录 use_channel 链路，并核对 shouldRetry 的阻断条件。

安全操作

排障日志只能使用脱敏 Token/Key、哈希后的 affinity key 和截断请求体。不要为复现问题临时关闭 IP 限制、SSRF 防护或账务校验；优先在隔离环境降低倍率和额度。
