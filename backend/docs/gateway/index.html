先用一句话理解网关

客户端请求先经过路由、鉴权、限流和渠道选择，再由 Relay 统一处理计费和重试，最后由 Adaptor 把内部请求转换成供应商协议。

完整代码链路见 请求生命周期；图形资源位于 backend/docs/gateway/assets/request-flow.svg。

文档的写作约定

  • “代码事实”给出文件、函数和关键分支，不把推测写成行为。
  • “学习提示”解释概念，不要求读者先理解全部 Go 代码。
  • “维护者提示”专门记录重试、计费安全、缓存/数据库兼容和扩展风险。
  • “可调参数”区分环境变量、后台配置、数据库字段和请求字段。
  • 未实现入口会明确标记 RelayNotImplemented。

多人格审阅机制

学习者作者先写场景和主线；普通开发者检查是否能跟着请求走；资深开发者检查并发、重试、账务和接口契约；项目参与者核对配置与扩展影响；博客编辑负责章节节奏；观察者把争议、证据和决议写入 review-log.md。
